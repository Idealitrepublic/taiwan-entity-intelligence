# 免費容量下的資料保存與發布規則

採用日期：2026-10-29。範圍限本機與 `tei-development`；不升級方案、不新增付費專案、不修改 Production。

## 兩層資料各自負責什麼

| 位置 | 保存內容 | 使用者可以在哪裡查到 |
|---|---|---|
| Git 外私有目錄 | 已取得的完整官方原件、SHA-256、來源網址、取得時間、匯入結果及版本 | 本機核對；不會自動出現在網站 |
| 本機 SQLite 來源索引 | 已取得的機關 OID、議案、董監事及公司捐贈來源觀察 | 本機查核；不是已發布 Entity |
| Development Supabase | 已審核發布的 Entity、Relationship、Evidence，及既有來源索引 | Development／Preview，仍受公開狀態與 RLS 限制 |

「完整原件」只指實際下載成功的那份檔案，不代表全國、所有年度或所有主管機關。
不得把本機索引筆數列成網站的可搜尋筆數，也不得以來源列數冒充已核對實體數。

## 實際配置與容量閘門

- 原件及來源索引位於工作區外的 `.tei-private-data` 私有資料夾；目錄 `0700`、檔案 `0600`，不加入 Git 或 Vercel。
- 已建立本機機關 8,030 筆、議案階段 7,690 筆／7,437 個議案 ID；不另外建立雲端正式實體。
- 目前 Development 資料庫實測 475,188,371 bytes。免費方案標示 500 MB；不把剩餘空間全部用完，須保留索引及日常寫入空間。
- 本輪政治／勞動批次發布工具設 480,000,000 bytes 寫入前停止門檻；共用來源發布入口另於逐批寫入前與提交前檢查。這是保守操作門檻，不是 Supabase 官方配額或保證。交易回滾也不保證立刻縮小已配置磁碟空間，仍需觀察實際大小。
- 暫停機關／議案等大型雲端擴充。其額外成本估算約 65 MB，並非精確配置量；原件與 SQLite 大小不能直接等同 PostgreSQL 圖譜成本。
- 司法同步沿用本機原件／Evidence／索引，不藉此增加 Supabase 全量資料表。同步完成仍須原有 Data Health 與發布驗收。
- 不刪除歷史或私人收藏來騰空間，不放寬 RLS，不使用 service-role key 作網站查詢，也不自動建立另一個付費資料庫。

費率與免費額度應於考慮擴充時重新查核：[Supabase 官方費率](https://supabase.com/pricing)。

## 雲端發布條件

1. 有官方來源、實際取得時間、不可變來源雜湊及來源列／頁碼。
2. 身分核對優先採統編或官方 ID；職務、選區、屆別、時間等訊號須能追溯。不以同名合併。
3. 已發布關係必須有已發布主 Evidence；無法辨識身分時保留來源觀察，不建立正式關係。
4. 可疑、返還、繳庫、非現金或更正紀錄分開覆核；空值不補零，不用假資料補 coverage。
5. 先核對去重、容量及交易範圍；交易失敗回滾。超出容量／來源範圍時停止雲端擴充，保留本機原件。
6. 僅在司法既有視窗完整處理、Data Health High=0 後，執行完整 DB checks、tests、build、Git 與 Preview 驗收。Production 另行授權。

## 保存與復原

原件以雜湊辨識，更新時保留先前版本；不得以重新執行時間冒充原始取得時間。
來源索引可由已保存原件重建；重建須核對 SHA-256、行數、SQLite integrity 與 foreign-key checks。
本輪寫入前已保留 age 加密 Development 備份；本輪沒有重新進行平台級完整還原演練。
私有目錄仍在這台 Mac：磁碟損壞風險尚在，不能冒稱雲端備援。外接磁碟或其他備援位置須由使用者指定後再另行配置，不上傳原件或憑證到未授權服務。
