# 左右資訊欄排版驗收

本輪先在本機修改並發布 Preview，待使用者確認後再同步正式版。

## 修改

- 左欄關係路徑的中英文標題、來源識別碼、日期及長網址可在欄寬內換行。
- 資料欄位採可縮小的雙欄，手機改為上下排列。來源標題與標記可換行。
- 判決與裁罰頁籤各只顯示一個官方查詢連結。
- 關係摘要和公司選擇器在這兩個頁籤隱藏，返回總覽後恢復。
- 公司、人物、機關與路徑資料背景載入使用相同的官方查詢內容，
  防止非同步回應重新寫入紀錄、空狀態或篩選器。

## 追修：左欄單行與標案內容

使用者要求左欄不再自動斷行。本節取代前述左欄換行設計；右欄長文仍依欄寬正常換行。

- 左欄名稱、欄位標籤、來源識別碼及日期使用單行，不省略字元。
  超出寬度可在各區塊左右捲動；欄位值靠左，避免短日期被長來源推到遠處。
- 標案頁籤隱藏兩家公司關係摘要，直接顯示所選公司的決標清單。
  路徑公司與索引公司皆更新實際載入筆數，並顯示目前查閱公司名稱。
- 切換公司清除前一公司的篩選條件；人物／機關只計入已載入的相關標案，
  不沿用前一家公司的筆數。未選擇公司時顯示選擇提示。
- 保留縣市、年度分類、篩選、逐筆公告與來源連結，不以圖上摘要節點數代替清單。
- 司法院與裁罰頁籤維持官方查詢連結，不恢復已撤下的資料。

## 追修：展開返回工具列與範例公司標案

- 根因：展開、關係摘要與分支按鈕原先插入標題區，與右側主工具列使用不同的排版，
  返回三欄畫面後會受標題寬度擠壓。現在改為共同工具區：置中／返回公司圖譜／清空在上，
  展開／關係摘要／分支操作在下。窄視窗可換列，畫布與手機清單依工具區實際高度避讓。
- 根因：點路徑公司雖然已載入標案，但仍保留總覽頁籤；資料被放在隱藏的標案 pane。
  現在點公司節點會直接選取該公司並打開標案，無須再點第二次頁籤。
  標案按鈕亦可先切換到指定公司，不再只支援原本已選取的公司。
- 來源核對：既有 Preview API 對聯上開發（22659295）回傳 8 筆，敦峰汽車（54690903）回傳 0 筆。
  這是當次查詢結果，不能以 0 筆推論該公司從未得標；不新增或偽造資料。
- 回歸：兩個公司節點鍵盤操作都能直接打開對應完整清單；1440／1280px 反覆展開／返回，
  以及 1024／768／390px 均確認操作列位於主按鈕下方、沒有超出畫面或遮住畫布。
  舊版回放會在「公司節點未打開標案」斷言失敗。
- 驗證：538 項 Python、250 項隔離 PostgreSQL 檢查、UI 函式測試、三組瀏覽器回歸、lint、build 通過。
  正式站及資料庫不修改；只發布獨立分支 Preview。

## 追修：企業總覽與鄰近展開

本節取代前一節「點公司強制打開標案」的互動，避免企業總覽看似消失。

Preview 實查另確認關係摘要排在企業總覽前，會佔滿右欄。
選定公司／單位後，摘要改排在總覽下方；切換公司或頁籤回到右欄頂端。
瀏覽器測試額外檢查實際公司名稱位於可見視窗內，不只檢查 DOM 內容存在。

- 路徑圖點公司回到該公司企業總覽，保留登記資料、人員、官網／165 與報告操作；
  同頁下方也列出已取得的標案，獨立標案頁籤與篩選仍可使用。不修改來源或資料庫。
- 新群組位置以實際子節點與原節點的最近距離評分；候選位置加入每個子節點對齊軸，
  不再只挑整個分類框中心較近、實際內容卻較遠的位置。沿用框線避讓與動態文字尺寸。
- 已載入節點與群組維持座標。大型展開不再自動縮小整張圖；必要時只小幅移動畫布，
  優先保留原節點可見。空間不足時仍可手動拖曳、縮放或按置中查看全圖。
- 驗證包含企業名稱／統編與標案同時存在、切換兩家公司、展開前後既有節點座標及倍率不變，
  寬群組實際最近節點選位，以及大型群組不拉走視角。
- 既有節點、來源、路徑、拖曳、分類框與避線測試保留；本輪不恢復撤下資料、不更新 Production。

## 追修：搜尋按鈕單行與同公司資料集中

- 「開始調查」及真實中介範例按鈕保留單行與完整中英文，不再被彈性寬度壓縮。
  中小視窗調整輸入欄位排列，320px 使用較小的範例按鈕字級，避免以截字解決溢出。
- 公司展開原先讓各分類獨立找最近空位，會分散在公司周圍。
  現在每家公司保留固定方向與面向公司的對齊欄線，各類來源依原分類集中於同側。
  中介路徑左端公司向左、右端公司向右；一般公司圖譜向外展開。
  後續批次及再次展開沿用方向，新增關聯公司亦擁有自己的展開欄位。
- 保留既有節點座標、手動拖曳、來源註記、分類框、Evidence、最短路徑與倍率；
  固定側內仍以最近可用位置排放並避免框線重疊，資料多時可拖曳或置中查看全圖。
- targeted tests 核對九種視窗寬度的按鈕文字、兩家公司多類資料與追加批次的同側／對齊、
  跨公司多層展開、既有節點不移位，以及線條不穿越無關分類框。
- 538 項 Python、250 項隔離 PostgreSQL 檢查、UI 函式測試、lint 與 build 通過。
  沒有資料庫寫入或正式站發布。

## 公開介面精簡

- 調查目標區名稱、提示及身分欄位按欄寬完整換行，不需水平捲動；其他來源欄位維持原設定。
- 範例按鈕改為「載入真實範例 / Load real example」。
- 移除工作區、登入表單及追蹤通知入口；不還原舊登入狀態、不自動呼叫私人 API。
  保留後端原有權限與資料，不變更 Supabase Auth、RLS 或任何使用者紀錄。
- 隱藏右上整體狀態標記，資料來源自身的不可用提示仍保留。
- 以 anon 唯讀聚合核對目前公開實體：一般 Person、PoliticalContribution、LegislativeBill 無已發布實體，
  移除對應下拉選項。人物圖譜及政治獻金 Relationship 不受影響，不刪除資料。
- 回歸驗證包含320–1920px、短搜尋提示、長名稱、舊 session 不觸發登入／通知請求，
  以及無登入視窗時仍可下載公開 PDF。僅發布 Preview，Production 不修改。

## 全左欄不需水平捲動

依最新要求，完整取代先前左欄單行／左右捲動設計。
調查目標、路徑說明與 Evidence、來源、統計、資料庫欄位皆按欄寬換行；
鍵值改為上下排列，路徑選單與查找按鈕各自一列，統計格允許文字換行。
不使用隱藏溢出或省略號掩蓋內容。瀏覽器回歸檢查每一左欄區塊的實際寬度、
長中英文來源與識別碼，並驗證企業總覽、標案及圖譜仍正常。
僅發布 Preview，不寫入資料庫或更新正式版。

## 標案關鍵字搜尋

- 來源角色「得標欄位命中」統一顯示「得標欄位符合」，包含既有角色文字，不改寫來源。
- 右側標案及總覽標案清單新增搜尋列，可按搜尋或 Enter 比對本次已載入的
  名稱、機關、案號、公司、統編、日期／年度與縣市。多個詞須全部符合，支援全半形與英文大小寫。
- 與原有分類篩選共同作用；清除篩選及切換公司會清除關鍵字。
  顯示篩選／載入筆數，無符合資料時明示空結果，不推論來源沒有其他公告。
- 不新增 API 或資料庫寫入，只部署 Preview。

## 標案案號與空值核對

介接 API 中仁愛路二段合建案的 job_number 為字串 `0630800011`，保留開頭零。
圖譜 AwardNotice 的「來源紀錄」改稱「案號 / Job no.」，其他類型維持來源紀錄原意。
本筆回傳有公告日期、機關、名稱、得標公司、案號、來源及取得時間，無金額、比例、
結束日期、觀察日期或 confidence。這些欄位明示「本次來源未提供」，不以零代替。
原先圖譜投影漏帶其他公告可用的 amount/currency，現已補上並測試零金額保留。
公告日期不再誤標為起始日期。官方使用者連結本輪無法直接讀取，未宣稱已獨立覆核官方明細。
沒有資料庫或 Production 修改。

## 標案概要精簡與待補資訊

標案關係詳情將目標實體改為「標案名稱 / Tender title」，案號緊接下一列。
移除標案的結束日期、觀察日期、比例、信心；其他種類關係仍保留這些欄位。

目前已有名稱、案號、機關、公告日期、得標公司、來源角色、來源與取得時間、分類與搜尋；
金額僅在本次來源有提供時顯示，尚非完整金額資料。下列為缺口盤點，不是已實裝承諾：

| 優先 | 尚缺資訊 | 核對重點 |
|---|---|---|
| 高 | 預算、決標總額、各得標商金額及幣別 | 分開存放，不能將預算或估算金額當作決標額；目前泛用 amount 不足 |
| 高 | 招標方式、決標方式／評選依據、採購性質 | 現有 notice_type 是公告種類，不是招標或決標方式 |
| 高 | 投標家數、完整廠商名單／統編、得標與未得標、各自報價 | 現有 company_names 不足以證實每家投標角色及報價 |
| 高 | 獨立決標日期、公告版本、官方明細永久連結／附件 | 現有公告日期與一般官方入口不能替代上述資訊 |
| 中 | 契約內容與變更、後續擴充、驗收及結算狀態 | 需另確認主管機關是否公開；不能以公告日期推論履約狀態 |
| 中 | 品項、數量、單位、履約地點及公開評選結果 | 依案件性質和公開範圍提供；未公開須明確標示 |

欄位範圍參照工程會[政府採購公告及公報發行辦法](https://www.pcc.gov.tw/content/index?eid=2850&lang=1&type=C)。
實際可取得內容仍須逐案核對官方明細；不代表每案皆公開每個欄位。
