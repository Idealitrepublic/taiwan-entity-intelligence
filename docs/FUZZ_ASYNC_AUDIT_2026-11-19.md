# 第二輪模糊測試：非同步操作與錯誤恢復

基準：`b3f80f4`，分支 `test/fuzz-async-workflows`。只在本機隔離環境執行高量測試；Production、資料庫、RLS、migration、環境設定均未修改。保留原有未提交備份檔變更。

## 這次改測的操作

本輪不使用上輪隨機展開／拖曳／縮放的操作表。新測試實際驅動現有 UI，以回應 gate 控制順序並注入可重現的失敗。

| 新流程 | 驗收重點 |
|---|---|
| 連續名稱搜尋，舊查詢最後才回 | 只能顯示最新提交的搜尋結果，舊 finally 不能重設新查詢按鈕 |
| 搜尋尚未回應時按 Escape、點外部、改送不完整關鍵字 | 已關閉的搜尋不得自行重新打開 |
| 公司來源尚未完成就選機關 | 舊公司標案不能把畫面拉回公司 |
| 機關概況尚未完成就搜尋另一家公司 | 舊概況不得覆蓋新公司 |
| 公司來源未完成就載入路徑範例 | 舊來源不能清掉新的路徑圖 |
| 路徑未完成就改查公司 | 遲到的路徑不能取代公司圖 |
| 1／2 中介切換與清除未完成路徑 | 舊範圍／舊端點不可復活 |
| 開啟標案明細後改用全形數字篩選，失敗後再重試 | 舊 slot 的錯誤不得污染目前篩選；有效摘要保留，失敗可重跑 |
| 重複按 PDF 下載 | 同一目標未完成時只有一個 request |
| HTTP 503、HTML 200、壞 PDF、網路失敗後重試 | 失敗不得成為下載；成功後檔案一致且舊錯誤提示清除 |
| PDF 下載中切到另一公司 | 檔名與內容仍對應原報告，現在畫面維持新公司 |
| 尚未完成時關閉 PDF 預覽視窗 | 不重新開啟、不產生下載，顯示可重試訊息 |
| 搜尋後取消但未更換目前公司 | 目前公司的有效來源仍能完成更新，避免漏資料 |
| 目前概況回應時，新搜尋結果仍開著 | 不可把較新的搜尋清單關掉 |

完整案例名稱與種子可在 JSON／腳本查閱。19 種流程各跑 3 種 seed，共 57 次瀏覽器工作流程；不是 57 種獨立功能。57 次均實際執行，沒有把未完成或跳過的流程列為 PASS。

## 找到並修復的問題

| 編號／嚴重度 | 實際重現 | 修復 |
|---|---|---|
| R2-01／High | 舊公司來源、舊實體概況或舊路徑，在新目標載入後覆蓋畫面；4 種跨流程情境重現 | 公司、實體及路徑採同一個目前調查世代；只讓仍屬目前調查的回應更新畫面。路徑保留 AbortController 取消。舊成功／失敗／finally 均受檢查。 |
| R2-02／Medium | 名稱查詢回應反序，或已 Escape 關閉後又被舊結果打開；2 種情境重現 | 名稱搜尋使用獨立世代與 active request，關閉／新搜尋／改選調查會淘汰舊結果；不讓舊 finally 解鎖新的查詢按鈕。 |
| R2-03／Medium | PDF 重試成功且已產生檔案，但原本的紅色失敗提示仍在；HTTP 503→重試已實際重現 | 開始新的公開報告重試時清除舊報告 feedback；保留重試若再失敗的正常提示。 |

最初用單一世代取消所有工作，額外 self-audit 發現「取消名稱查詢後，目前公司的來源也停止更新」的回歸。已在本機改為分開管理搜尋清單與目前調查，並加入兩項保留來源／保留搜尋清單的真實瀏覽器回歸；該中間版本未推送部署。

初始失敗證據：seed `91021`，6 個跨回應／關閉失敗，加上單獨測得的 PDF 舊提示失敗。沒有以放寬斷言或忽略錯誤使其通過。

## 限制

這是固定預算、控制回應順序的 UI／函式測試，不是全站所有輸入的形式驗證、負載測試或滲透認證。除了既有路徑取消外，部分舊 fetch 可能在背景完成，但其結果不再更新不屬於它的畫面。RLS 與資料真實性沒有因本輪而重新全量覆核，不宣稱零漏洞或全國資料完整。
